## Contract and decisions

Contract written first in [contracts.md](../contracts.md#p10-c2b-website-embed-and-customer-self-service).

- Use Caddy `forward_auth` against org's `/api/v1/public/embed-policy?path=...`; copy `X-Embed-CSP` into
  the request, then set the document CSP from that header before serving widget.html. Unknown/empty/disabled
  businesses fail closed. No service/container and no frontend asset discovery in the API. Production script-src
  stays self-only; the dev proxy permits Vite's inline refresh preamble. COOP/COEP are unsafe-none on embed only.
- Use an iframe sessionStorage/header capability with an in-memory fallback. No embed cookie is issued; the
  first-party visitor's HttpOnly/Secure/SameSite=Lax cookie/path is unchanged. Reload loses the conversation when
  storage is blocked; a live page keeps working. X-Embed-Token is redacted from Caddy request/response logs.
- Exact normalized HTTPS origins only, up to ten; dev HTTP localhost allows exact ports (including default 80), never a wildcard.
  The loader fetches only public label/config with credentials omitted and exact allowlisted CORS. Frame messages
  are open/close/resize only, checked by origin + window source + message shape; no customer data crosses frames.
- Self-service is a customer visitor action (`act_notify`), outside AI proposals/permissions/budgets. Requested
  transactional e-mail needs no marketing grant; complete e-mail opt-out/preference and inactive states block it.
  A database trigger revokes capabilities on lifecycle transitions, including archive -> reactivation, and cancels
  queued self-service mail on complete e-mail opt-out.
- Token/session tables contain only SHA-256 capability hashes. The private delivery outbox necessarily contains
  the fragment link; it is never in a public response or exported capability variable. Links expire in 20 minutes,
  are single use, and exchange for a path-scoped Strict cookie with a sliding 60-minute idle expiry.
  A new exchange revokes the browser's previous session; fragment-only navigation and stale responses are guarded.
- Lock customer first, then token/session/appointment. Every read/change rechecks live eligibility and tenant +
  customer ownership. Version conflicts return 409. Fee acknowledgments bind to the exact currently displayed
  policy, so a changed policy requires review again; the receipt captures text/boolean/time/version.
- Reschedule calls canonical find_slots and place_hold, consumes that temporary hold within the transaction,
  then uses canonical reschedule to retain booking id and inventory reservations. Service/location cannot change;
  the P10-E1 slot implementation will be reused through these same calls. Do not create a second booking.
- No public staff-name flag exists on this branch; omit staff names. Public booking DTOs omit identity, notes,
  prices and operational metadata. Slots omit resource names. The demo seed enables self-service for its synthetic
  businesses; existing deployments can enable it explicitly in settings without reseeding.
- The existing outbox DTO omits message bodies. Add a read-only, tenant/customer-read and owner/admin protected simulated-mail
  projection; the minimal Settings UI is shown to owners/admins (settings-write + customer-read). Real email-channel
  rows, restricted/erased bodies and messages older than 24 h are excluded. No mail provider or send action is added.
- Bookings and supplier quote screens load on their routes to retain the public bundle budget. Copy uses the existing
  English i18n source; bookings copy is projected at build time without loading staff translations/i18next.
- TypeSafe was considered; all authorization, eligibility and fee checks here require deterministic rules. No
  semantic judgment or inference/API call was added.
